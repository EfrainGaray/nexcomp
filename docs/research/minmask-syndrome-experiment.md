# MinMask: minimum-description mask + sparse XOR residual + syndrome coding

Research report for the NEXCOMP experiment branch `research/minmask`.
Baseline: branch `perf/lzma-drop-literal-mtf` at `04a4fde` (NX13 container, 4 MiB blocks,
LZMA with binary-tree optimal parsing, BWT + context mixing, PPM with update exclusion).

## Executive Summary

**The primary hypothesis did not hold on real data.** On Calgary, Canterbury, Silesia and enwik8
(42 files, 318 MB) MinMask is larger than NEXCOMP on every file, with FAST and with EXHAUSTIVE
search. Used as one more per-block candidate inside NEXCOMP it is never selected: the hybrid
saves 0 bytes on all four corpora. No cheap mask makes a real file sparse: the chosen residuals
keep 11–49% of their bits set, and for text the winner is no prediction at all (the `zero` mask,
i.e. the raw bytes through order-0 rANS). The sparse coders (positions, Rice, enumerative, BCH)
never get a sparse residual to work on, and a residual coded without context loses to LZMA and
the BWT context mixer.

**BCH syndrome coding never beat enumerative coding, and it cannot.** It ties at t = 1 (the
perfect Hamming code) and at n = 1023 spends 1, 4, 15, 44, 113, 238 and 348 bits more than the
floor for t = 2, 4, …, 128, while the enumerative rank stays within one bit of log2 C(n, t).

**Where the technique works (Tier C):** data generated by, or very close to, a mask family:
PRBS streams (35 bytes against NEXCOMP's 31 605), short periods (−49% to −67%), linear counters
and jittered timestamps (−94%, −26%), and near-duplicate blocks with sparse bit flips (−1% to
−7%).

**Decision: KEEP EXPERIMENTAL.** MinMask stays an isolated research codec. `CodecId::MinMask`
is not added, the NEXCOMP wire format is unchanged and the README is untouched.

## Mathematical Model

A block X of n bits is described by a mask family F, parameters θ, a complement flag c,
a residual codec R and its payload:

```
M = F(θ, previously decoded bits)      E = X xor M xor (c ? 1^n : 0^n)
C(M) = |family id| + |θ| + |c| + |codec id| + |codec metadata| + |payload(E)|
```

The encoder picks the (F, θ, c, R) that minimizes C over its candidate set; the decoder reads
F, θ, c, R and the payload and rebuilds X = E xor M causally, bit by bit where M depends on
bits of the same block. The mask with the lowest Hamming weight is not necessarily chosen: a
pattern mask of 64 bits that removes 10 flips loses to a free `zero` mask if the flips cost
fewer than 67 bits to name. Every block pays 4 bits of family id, 1 complement bit and
3 bits of codec id; every MinMask payload pays a 5-byte header (length + configuration); when
MinMask sits inside the NEXCOMP container it pays the same 10-byte block header as any codec.
The trivial mask M = X would make E = 0 but costs |θ| = n bits, so families are restricted to
masks whose parameters are short: fixed patterns of at most 64 bits, stride/distance copies of
earlier bits, byte extrapolation, seeded PRBS generators, Berlekamp-Massey LFSRs (charged 2L
bits) and match-plus-pattern combinations.

**Sparse floor.** If E has weight t, naming which t of the n positions flipped needs
log2 C(n, t) bits when n and t are known. Enumerative coding reaches ⌈log2 C(n, t)⌉ by storing
the rank of the set of positions in the combinatorial number system; the codec also pays
Elias-gamma(t + 1) to transmit t.

**BCH syndrome.** For n = 2^m − 1, the binary primitive BCH code with designed distance 2t + 1
has generator g_t = lcm(m_1, …, m_2t) of degree at most m·t. The residual is sent as t and
r(x) = E(x) mod g_t(x) (deg g_t bits). Because the code corrects t errors, every E of weight
≤ t is the unique minimum-weight pattern with that syndrome, and Berlekamp-Massey plus a Chien
search recovers it. The encoder offers BCH only with t = weight(E) ≤ (n − 1)/2; a heavier E
has no unique decoding under that code and is never emitted (tested).

**Why BCH cannot beat enumerative coding.** Any syndrome former that uniquely decodes every
pattern of weight ≤ t must map Σ_{i≤t} C(n, i) patterns to distinct syndromes, so it needs at
least log2 Σ_{i≤t} C(n, i) ≥ log2 C(n, t) bits (the Hamming bound). Equality holds only for
perfect codes (t = 1 Hamming codes). With the usual estimate
log2 C(n, t) ≈ t·(m − log2 t + log2 e), BCH's m·t exceeds the floor by about
t·(log2 t − 1.44) bits, which grows superlinearly with t. Experiment B measures this.

## Implementation

Files (all new code is isolated; the NEXCOMP wire format is unchanged):

| file | role |
|---|---|
| `src/codecs/minmask/mod.rs` | format, layouts, candidate generation, two-stage search, decoder |
| `src/codecs/minmask/masks.rs` | mask families, exact description cost, causal reconstruction, match index, binary Berlekamp-Massey |
| `src/codecs/minmask/residual.rs` | residual codecs with exact bit costs |
| `src/codecs/minmask/enumerative.rs` | big integers, exact rank/unrank in the combinatorial number system |
| `src/codecs/minmask/bch.rs` | GF(2^m) for m = 8..13, BCH generators, syndrome former, Berlekamp-Massey, Chien search |
| `src/codecs/minmask/bits.rs` | bit vectors, bit-exact writer/reader, Elias-gamma, Rice |
| `src/codecs/bwt_cm.rs` | its binary arithmetic coder is now `pub(crate)` so `arith` residuals reuse it |
| `tests/minmask_experiment.rs` | experiments (all `#[ignore]`) |

**Wire format.** `[4B length][1B config: layout bit + block size id]` then one bitstream with,
per block, `mask | complement | codec id | residual`.

**Layouts.** Linear (byte0 bit7…bit0, byte1 …) and bit planes (bit 0 of every byte, then
bit 1, …). Both are exactly reversible and tested.

**Block sizes.** 255, 511, 1023, 2047, 4095, 8191 bits (BCH lengths) and 256 B, 512 B, 1 KiB,
4 KiB, 16 KiB, 64 KiB. The block size id lives in the 1-byte config.

**Mask families** (id is 4 bits; parameters as listed):

| family | parameters | bits |
|---|---|---|
| zero (ones via complement) | – | 4 |
| pattern | length index (2,4,8,16,32,64 bits) + pattern | 7 + L |
| stride (xor delta) | stride index (1,2,4,…,64 bytes) | 7 |
| prev-block | – | 4 |
| match (dictionary/rotation) | Elias-gamma distance in bits | 4 + γ(d) |
| add-delta | stride index; predicts 2·B[i−s] − B[i−2s] (linear layout only) | 7 |
| lfsr | polynomial id (PRBS7/15/23/31) + seed | 6 + deg |
| bm-lfsr | γ(L+1) + L connection bits + L seed bits (blocks ≤ 8192 bits) | 4 + γ + 2L |
| two-stage | match distance + pattern | 4 + γ(d) + 3 + L |

Alternating patterns (01, 0011, 00001111) are patterns of length 2, 4 and 8; ONE is ZERO with the
complement flag; previous-byte and previous-word predictors are strides of 1, 2 and 4 bytes; the
rotated previous block and repeated sub-blocks are matches at the corresponding distance.

**Residual codecs** (id is 3 bits): `raw`; `rle` (run count, first bit, Elias-gamma runs);
`positions` (t, then ⌈log2 n⌉ bits per set position); `rice` (t, 4-bit k, Rice-coded gaps;
k chosen exactly); `enumerative` (t, then the rank in exactly ⌈log2 C(n,t)⌉ bits, for t ≤ 1024
or n − t ≤ 1024); `bch` (t, then E mod g_t; n = 2^m − 1, t ≤ (n − 1)/2); `arith` (adaptive
binary arithmetic coding with an order-1 bit context and KT counts); `rans` (NEXCOMP's static
rANS over residual bytes, with its 256 × 13-bit frequency table). `raw` is always available as
the lossless fallback.

**Search.** Stage 1 scores every candidate mask and both complement polarities with exact costs
for `raw`, `rle`, `positions`, `rice`, `enumerative` and `bch`, and with ranking estimates for
the two codecs that need a full encode (`arith`: order-1 KT code length; `rans`: byte entropy
plus its table). Stage 2 computes the exact cost of every codec for the 3 best masks and keeps
the smallest. The serialized size is always the exact written size. `rank_width` decides
⌈log2 C(n, t)⌉ from a Kahan-summed log2-factorial table and falls back to exact big-integer
arithmetic when the value lies within 10⁻⁵ of an integer, so encoder and decoder always agree.

- FAST: linear layout; blocks of 1023 bits, 1 KiB, 4 KiB; masks zero, prev-block, patterns of
  2/8/32 bits, strides 1/2/4 bytes, add-delta stride 1, 2 match distances from a byte-aligned
  32-bit window index.
- EXHAUSTIVE: both layouts × all 12 block sizes; all patterns, strides and add-delta strides,
  4 PRBS masks, Berlekamp-Massey LFSR, 16 match distances at 2 anchors, and two-stage masks
  built on the 3 best copy masks.

Search decisions depend only on the input bytes; there are no file-name rules.

## Correctness

All comparisons are direct byte-for-byte equality; there were zero mismatches.

| check | coverage |
|---|---|
| full codec round trip | 10 inputs (empty, 1 byte, zeros, ones, alternating, periodic, sparse flips, numeric, text, random) × 2 layouts × 12 block sizes × FAST/EXHAUSTIVE = 480 round trips |
| fuzz | 2000 deterministic random inputs of 0–699 bytes (random, periodic with sparse flips, ramps, sparse bytes), random layout and block size |
| truncation | every prefix of a payload decodes to an error or a value, never a panic |
| accounting | reported bits per block sum to the serialized size for every test input |
| residual codecs | 9 (n, t) cases × 8 codecs: decode equals input and written bits equal the search cost; Experiment B repeats this for 200 residuals × 8 weights × 3 lengths × 8 codecs |
| BCH | fields m = 8..13 are generated by a primitive element; syndromes decode every pattern of weight t ∈ {0, 1, 2, 3, 8, 16, 33} at n = 255, 1023, 8191; a pattern of weight t + 1 is never returned as the decode of a t-syndrome; the encoder refuses BCH above the design limit |
| enumerative | rank is a bijection on all 3-subsets of 10 positions; random round trips up to n = 65536; the fast rank width equals the exact big-integer width for every t ≤ 600 at five lengths; out-of-range ranks are rejected |
| masks | for 10 families × both complement flags, the decoder's causal reconstruction equals the encoder's mask, and written bits equal the declared cost; Berlekamp-Massey recovers PRBS15 with 15 taps |
| experiments | every synthetic and corpus run decompresses and compares (column "lossless") |

Random data (Experiment C) never compressed: the best result was raw plus framing, which is the
sanity check the design called for.

- **A, exact predictors (−67% to −99.9%).** The data is generated by a mask family, so the
  residual is empty (0–2 bits) and the output is headers plus 11–25 bits of mask description
  per block. PRBS15 is the extreme case: 35 bytes against 31 605, because a 2^15 − 1 bit period
  is not byte-aligned and byte-oriented LZ and context models only see it repeat after 32 KiB.
  FAST has no LFSR family and gets 20 644 bytes.
- **C, random data (±0%).** Raw residual plus framing; no gain appears where none can exist.
- **D, periodic data (−3% to −67%).** One copy mask per block with an empty residual; LZMA pays
  a match every 273 bytes. The gain shrinks as the period grows because the first period costs
  the same in both.
- **E, numeric data: wins and losses.** A u32 counter drops from 18 023 to 1 050 bytes (−94%)
  and timestamps with jitter from 62 483 to 45 988 (−26%): `add-delta` (2·B[i−s] − B[i−2s] with
  the element stride) predicts almost every bit, and NEXCOMP neither tries its delta codec on
  these blocks nor has a linear predictor. A noisy sine (+29%) and a random walk (+22%) lose:
  their residuals stay dense or structured by bit position, and an order-0/1 residual coder
  cannot compete with LZMA's literal contexts or the BWT context mixer.
- **F, previous block with sparse flips (−1% to −7%).** The strongest case the design predicted:
  `prev-block` plus `enumerative` pays about log2 C(n, t) per copy, while LZMA pays a rep-match
  restart plus a literal per flipped byte.

- **Masks alone do nothing.** With a raw residual, Calgary comes out at the input size plus
  framing: the gain comes entirely from coding E, never from the mask by itself.
- **Residual codecs rank as the theory says.** Among the sparse coders, enumerative < Rice <

  constraints (block length 2^m − 1 and t ≤ (n − 1)/2), so on the periodic and near-duplicate
  sets it falls back to raw for most blocks. On real data the best single codec is `arith`,
  because the residuals are dense.
- **Layouts.** Linear wins on Calgary, periodic and near-duplicate data; bit planes win on the
  u32 counter (a few planes carry all the change) and on the PRBS stream.
- **FAST vs EXHAUSTIVE.** On Calgary the larger search buys 0.1%; on data that matches a

  candidates pushed the true winner out of the three finalists. The ranking now uses the
  order-1 KT code length for `arith` and the byte entropy for `rans` (unit-tested within 2% of
  the exact costs), and EXHAUSTIVE is never worse than FAST in any row. All numbers in this
  report come from the corrected version.

## BCH vs Enumerative

At n = 1023 the syndrome of the t-error-correcting BCH code costs 10, 20, 40, 80, 160, 315,
580 and 900 bits for t = 1, 2, 4, …, 128, against a floor of 10.0, 19.0, 35.4, 64.6, 115.6,
201.6, 341.0 and 551.7 bits. The enumerative rank costs 10, 19, 36, 65, 116, 202, 342 and 552
bits: never more than one bit above the floor. BCH matches it only at t = 1, where the BCH
code is the perfect Hamming code; at t = 128 it spends 348 bits (63%) more.

The same shape holds at n = 255 and n = 8191 (8191, t = 128: 1638 syndrome bits against a
947-bit floor). BCH is, in practice, position coding: `positions` (t·⌈log2 n⌉ bits) and BCH
cost the same up to t = 16 at n = 1023, and BCH pulls ahead of positions only once cyclotomic
cosets start to repeat (t ≥ 32). Rice coding of the gaps stays within 3 to 15 bits of the
enumerative total. The adaptive `arith` coder pays about 40 bits of fixed overhead, so it only
approaches the others once t reaches the hundreds.

This is the Hamming bound at work, not an implementation weakness: a syndrome that uniquely
identifies every error pattern of weight ≤ t needs at least log2 Σ_{i≤t} C(n, i) bits, which
is never less than log2 C(n, t). Sending t plus the enumerative rank is the better description
of a sparse residual whenever the decoder can afford the big-integer unranking. BCH's real
advantage (algebraic decoding without big integers) does not translate into fewer bits.

## Best Cases

All wins are on data built from one of the mask families; none of the 42 standard files is a
win.

- **Generated sequences.** A PRBS15 stream is a 15-tap linear recurrence over bits whose period
  (2^15 − 1 bits) is not byte-aligned, so byte-oriented LZ and context models only see it repeat
  after 32 KiB. The `lfsr` mask describes each 64 KiB block with 21 bits of seed and polynomial,
  and the residual is empty: 35 bytes against 31 605 (NEXCOMP) and 31 648 (xz).
- **Linear numeric data.** For a little-endian u32 counter, `add-delta` with stride 4
  (2·B[i−4] − B[i−8]) predicts every byte except carries: 1 012 residual bits over 2 Mbit,
  1 050 bytes against 18 023. Timestamps that grow by 1000 ± 8 keep only the jitter byte
  (−26%). NEXCOMP's classifier does not try its delta codec on these blocks, and that codec has
  no linear predictor.
- **Periodic data.** One copy mask per block with an empty residual; LZMA pays a match every 273
  bytes (−49% to −67% for periods of 3 to 64 bytes).
- **Near-duplicate blocks with sparse flips.** `prev-block` + `enumerative` pays about
  log2 C(8192, t) + γ(t + 1) + 8 bits per 1 KiB copy; LZMA pays a rep-match restart and a
  literal per flipped byte. This is the case the design singled out, and it wins, but only by
  1–7%.
- **Closest real files.** Only numeric and image data came near: `geo` (32-bit samples) at
  +3.5% with EXHAUSTIVE, the `x-ray` sample at +6%, `mr` at +20%. The masks used there are
  strides and bit planes.

## Failure Cases

- **Text** (book1, paper*, dickens, webster, enwik8, …). The search settles on no prediction at
  all: the `zero` mask, whose residual is the text itself (about 45% of its bits set), coded
  by order-0 rANS at 5.3 bits per byte for book1 against 2.2 for NEXCOMP. Masks such as a
  period-8 pattern for the ASCII high bit are bijections on byte values, so they cannot lower
  an order-0 byte cost; the redundancy of text lives in variable-length contexts that no
  single cheap mask per block can express.
- **Repetitive structured files** (nci, xml, osdb, kennedy.xls, samba). They repeat substrings
  at many different distances. LZ parsing switches source every few bytes; one `match` mask per
  block cannot, so most of the block stays unpredicted (nci +798%, xml +882% with FAST).
- **Executables** (mozilla, ooffice, obj1/obj2). Same reason, plus no fixed stride.
- **Noisy numeric data** (sine + noise +29%, random walk +22%). The residual is not sparse; its
  structure depends on the bit position within each sample, which an XOR followed by an order-0
  or order-1 bit coder cannot see.
- **The common cause.** If a predictor is right with probability p on some bits and 1 − ε on
  others, XOR turns all of them into a residual coded at the average density. A context model
  that conditions on the predicted bit and its position pays H(p) where the prediction is weak
  and almost nothing where it is strong. LZMA's matched literals and the BWT context mixer do
  exactly that, which is why they win on every real file.

## NEXCOMP Integration Decision

**KEEP EXPERIMENTAL** (Tier C).

- Tier A needs a reduction on at least one standard corpus after adaptive selection: the hybrid
  saved 0 bytes on Calgary, Canterbury, Silesia and enwik8, because MinMask won none of the
  container blocks.
- Tier B needs substantial wins on specific real files or blocks: none were found (the closest
  file is 3.5% larger).
- Tier C holds: the synthetic experiments characterize exactly where sparse-predictor residual
  coding wins (generated, periodic, linear-numeric and near-duplicate data).

Integration would also cost speed for no gain: FAST encodes at about 0.6 MB/s and EXHAUSTIVE
at about 0.02 MB/s, so MinMask would be the slowest candidate in the selector. The codec, its
tests and the experiment harness stay in the tree for further research; nothing in the
production path references them.

## Next Experiment

**Use the predictor as a context instead of subtracting it.** The two findings point the same
way: the only wins near real data came from exact linear prediction (counters, timestamps), and
the losses came from XOR discarding how reliable the prediction is per bit. The follow-up is a
stride-aware prediction model inside NEXCOMP's binary context mixer: detect the element stride
of a block, predict each byte as 2·B[i−s] − B[i−2s] (and the byte one stride back), and feed the
predicted bit and the bit position as contexts to the mixer that already codes BWT output.
Where the prediction is exact it costs a few bits per block, as MinMask did; where it is only
partly right (noisy numeric, images such as mr and x-ray, geo) the mixer learns per-position
confidence. Success criterion: beat NEXCOMP on the Experiment E sets and on Silesia's numeric
files, with zero regressions after adaptive selection.
